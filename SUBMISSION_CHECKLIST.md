# Hackathon Submission Checklist — Governed ChronoMemory-OS

Cross-check of the current implementation against `rules.txt` (Global AI Hackathon
Series with Qwen Cloud, Official Rules) — Track 1: MemoryAgent. Generated by
reading the actual repo state (code, `git ls-files`, `gh repo view`), not from
memory of what should be there.

## Track fit (Track 1: MemoryAgent) — already satisfied

The track asks for efficient storage/retrieval, timely forgetting, and
recalling critical memories within limited context windows. All three are
genuinely implemented:

- [x] Retrieval — `read_path/recall.py` (dual-recall search)
- [x] Forgetting — `read_path/decay_scorer.py` (Weibull-style decay + prune threshold)
- [x] Limited context windows — `core/trim.py` trims assembled context to a
      char budget, dropping lowest-priority entries first
- [x] Real Qwen Cloud usage — `core/qwen_client.py` hits Qwen Cloud's endpoint
      with three distinct model roles (agent / extractor / scorer), not one
      model doing everything

## Hard submission requirements (Section 4) — currently failing or missing

- [ ] **Open-source license file.** `gh repo view` shows `licenseInfo: null`
      on the public repo; no `LICENSE` file exists locally either. Rule:
      *"must be public and open source by including an open source license
      file... detectable and visible at the top of the repository page (in
      the About section)."* Repo is public; license is not present. Add a
      `LICENSE` file (e.g. MIT/Apache-2.0) at repo root.
- [ ] **README doesn't describe the project.** Current `README.md` is 12
      lines of file layout only — no problem statement, no features, no
      usage instructions, no architecture diagram. Rule requires a text
      description of features/functionality and an architecture diagram
      showing how Qwen Cloud connects to backend/database/frontend.
- [ ] **Real documentation is gitignored and never pushed.**
      `governed-chronomemory-os-overview-v3.md` and the phase1-3
      implementation guides/reports are all listed in `.gitignore` — a judge
      cloning the public repo cannot see them. Either untrack-and-commit the
      relevant ones, or fold their content into the README/docs that *are*
      tracked.
- [ ] **No testing instructions for judges.** The app now requires real
      password login (self-serve signup). Rule: *"If Entrant's website is
      private, Entrant must include login credentials in its testing
      instructions."* Nothing in the repo currently tells a judge how to
      reach a running instance or log in — no deployed URL documented, no
      seeded demo account, no testing-instructions doc.
- [ ] **Demonstration video** (< 3 min, publicly hosted on YouTube/Vimeo/Youku)
      — not trackable from the repo; confirm this exists and is linked on
      the Devpost submission form.
- [ ] **Blog/social post** (optional, for the Blog Post bonus prize) — same,
      confirm separately if pursuing that prize.
- [ ] **Explanation of what changed during the Submission Period.** Rule
      requires explaining how a pre-existing project was "significantly
      updated" during the Submission Period (May 26 – Jul 20, 2026) if it
      existed beforehand. Worth a short paragraph in the README/submission
      text if this project predates the hackathon.

## Known gaps the project's own design doc already flags

From `docs/superpowers/specs/2026-07-18-per-user-memory-isolation-design.md`:

- [ ] **Connection pooling.** `app.py`'s `get_connection()` is
      `@st.cache_resource`, so one Postgres connection is shared across
      *every* concurrent user session in the same Streamlit process. Fine
      for a single demo user; will misbehave under concurrent judges/testers
      hitting the same deployed instance.
- [ ] **No eval harness** for retrieval / contradiction-resolution /
      poisoning-detection accuracy. "Algorithm & engineering innovation" is
      30% of the judging score — having measured numbers (precision/recall
      on recall, contradiction-detection accuracy, VIGIL flag precision)
      would strengthen that claim instead of relying on a text description.
- [ ] **VIGIL held-fact review loop isn't closed out.** The Flagged tab can
      promote a held fact to trusted memory, but there's no reject/dismiss
      path — a flagged fact can only ever go forward to trusted, never be
      discarded.
